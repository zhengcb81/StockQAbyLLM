# StockQA 整改发现

- 实际资金许可预检保留。独审批次证实原拒绝结果和 F4 采用两个运行号，且双诊断 I/O 故障会让常规日志缺原拒绝。入口采用同一 run/attempt，拒绝仍保持原码、退出状态和单条 stdout。
- 原生收件和投影均不可写时把完整的脱敏收据落到既有轮转日志，并在 stderr 回报同一标识。全写故障下公开冷读明确原证据不可得。只读查找以原编号和原日志/收件目录为参数。
- 发送边界在外部调用前记录原 attempt。CLI 终态、收到响应和账本提交由各自事实表示。强停后只有派发意图时，冷读标明结果和费用未知，已付去重由原账本继续负责。
- 公共异步单入口和批入口共享一个调用域，聚合保留每题引用和原异常结构，移除查询及异常原文重复写日志。题级成功和诊断失败遵循不同状态，观测不会启动第二次运输。
- 独审发现异步终止分支先把运输异常转换成业务结果，返回后只能构造空因果的泛化失败。修正后由 provider 在转换前按本题记录原异常链、公开请求 ID 和运输尝试引用。并发题共享宿主运行，分别保留请求引用。可疑请求标识保存摘要，费用证据缺失时保持未知。
- 响应和冻结模型解析归到账本自有读层，pack journal 通过共享值与读函数复用原验证。传输只调用高层证据查询和原子发布/释放；结果投影和已付编排可以消费独立的只读协议。当前写操作仍持有所属账本签发的运输授权。
- 独审发现已付冷读只匹配工作项、代数和原账本 attempt，允许移用已核验费用到其他宿主运行。现有反馈绑定 SQLite 同时记录真实发布的宿主 run/attempt。历史 ready 记录能证明原组合时继续适用。只有丢失外层标签的原生读请求可退回精确原账本定位，避免在无证明时推断宿主关系。
- C06 独占组合现场与宿主投产结果沿用原计划的后续验证。此次候选只验证独立真实入口和合成运输，成本为零。
